# Brainstorming

1. **Explore context** - look at the existing project (files, README, recent commits) so questions are informed.
2. **Classify the size** - a small change needs a two-sentence design; a new project or subsystem needs a
   fuller design. Say which you think it is.
3. **Ask clarifying questions ONE at a time** (AskUser, with 2-4 concrete options where possible) about
   purpose, users, constraints and what "done" looks like. Stop when you can design confidently.
4. **Propose 2-3 approaches** with trade-offs; lead with your recommendation and why. Remove anything not
   needed (YAGNI).
5. **Present the design** - components, data flow, error handling, testing - scaled to the task.
6. **Get explicit approval before implementing.** Then plan (planning skill) and build.

Never start writing implementation code during brainstorming.
